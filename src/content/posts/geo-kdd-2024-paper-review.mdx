대규모 언어 모델(LLM)과 검색엔진이 결합한 BingChat, Google SGE(현 AI Overviews), Perplexity.ai 같은 **생성형 엔진(Generative Engines, GE)**은 사용자의 정보 탐색 효율과 플랫폼 수익을 동시에 끌어올렸다. 그러나 이 전환은 검색 생태계의 제3 이해관계자인 **웹사이트·콘텐츠 크리에이터**에게 직접적인 위기를 안겼다. 사용자가 링크를 클릭해 웹사이트로 이동하지 않고 생성된 답변에서 바로 답을 얻기 때문에 유기적 트래픽이 감소하며, 블랙박스 구조 탓에 크리에이터는 자신의 콘텐츠가 어떻게 수집·요약·노출되는지 통제할 수 없기 때문이다.

IIT Delhi(Pranjal Aggarwal), Princeton University(Vishvak Murahari, Karthik Narasimhan, Ameet Deshpande), Independent(Tanmay Rajpurohit, Ashwin Kalyan) 연구진이 **ACM SIGKDD 2024**에서 발표한 **GEO: Generative Engine Optimization**은 이 문제에 대응하는 최초의 크리에이터 중심 최적화 프레임워크다.

### 논문의 3대 핵심 기여
1. **최초의 일반화 가능한 GEO 프레임워크 제안:** 비공개·블랙박스 생성형 엔진을 대상으로 웹사이트 텍스트를 최적화해 가시성을 최대 40%(실서비스 Perplexity.ai 최대 37%)까지 높이는 방법론을 정립했다.
2. **생성형 엔진 전용 다차원 가시성(Impression) 지표 정의:** 단순 링크 순위가 무의미해진 환경에서 객관적 지표(`Position-Adjusted Word Count`)와 주관적 지표(`Subjective Impression`)를 설계하고, 크리에이터가 맞춤형 지표를 정의할 수 있게 했다.
3. **대규모 벤치마크 `GEO-bench` 구축 및 공개:** 9개 데이터셋·25개 도메인에서 수집한 10,000개 쿼리와 상위 5개 웹 문서를 결합한 최초의 GEO 표준 평가 벤치마크를 공개했다.

## 1. 생성형 엔진(GE)의 수학적 정식화와 파이프라인

논문은 상용 생성형 엔진의 내부 모듈을 하나의 통합 함수로 정식화한다(Section 2.1). 사용자 질의 `q_u`와 개인화 정보 `P_U`가 입력되면 자연어 응답 `r`을 반환하는 함수 `f_GE := (q_u, P_U) → r`은 두 핵심 요소—**생성 모델 집합 `G = {G₁, G₂, ..., Gₙ}`**과 **검색엔진 `SE`**—로 구성된다.

<figure style="margin: 1.75rem 0; padding: 1rem; background: #ffffff; border: 1px solid var(--border); border-radius: var(--radius);">
  <img src="/images/geo-kdd-2024/figure-2-ge-pipeline.png" alt="Figure 2: 생성형 엔진(Generative Engine)의 전체 파이프라인 구조도" style="width: 100%; max-width: 620px; height: auto; display: block; margin: 0 auto; border-radius: 6px;" />
  <figcaption style="margin-top: 0.75rem; font-size: 0.88rem; color: var(--text-muted); line-height: 1.55;">
    <strong>Figure 2 (원문 p.3):</strong> 생성형 엔진의 대표 워크플로(집필 시점 BingChat 구조와 유사). 질의 재작성(<code>G_qr</code>) → 검색엔진(<code>SE</code>) 문서 검색 → 요약 모델(<code>G_sum</code>) → 인라인 인용 포함 응답 생성 모델(<code>G_resp</code>)의 4단계로 작동한다.
  </figcaption>
</figure>

1. **질의 재작성 (`G₁ = G_qr`):** 복잡한 사용자 질의 `q_u`를 검색엔진이 처리하기 쉬운 하위 검색어 집합 `Q₁ = {q₁, q₂, ..., qₙ}`으로 분해·재작성한다.
2. **문서 검색 (`SE`):** 검색엔진이 하위 검색어에 대해 순위가 매겨진 웹 문서 집합 `S = {s₁, s₂, ..., sₘ}`을 추출한다.
3. **문서 요약 (`G₂ = G_sum`):** 각 문서 `sⱼ`의 핵심 내용을 요약한 집합 `Sum = {Sum₁, Sum₂, ..., Sumₘ}`을 생성한다.
4. **인용 기반 응답 생성 (`G₃ = G_resp`):** 요약 집합을 바탕으로 문장 `{l₁, l₂, ..., lₒ}`로 구성된 구조화 응답 `r`을 합성하며, LLM 환각을 억제하기 위해 각 문장에 근거 출처 집합 `Cᵢ ⊂ S`를 인라인 인용(`[1]`, `[2]`)으로 부착한다. 이상적인 GE는 높은 **인용 재현율(citation recall)**과 **인용 정밀도(citation precision)**를 동시에 충족해야 한다(Liu et al., 2023).

- **다중 턴 대화형 엔진 확장 (Appendix A):** 후속 질문이 이어지는 대화형 GE는 단일 질의 `q_u` 대신 대화 이력 `H = (q_u^t, r^t)`를 입력받아 `r^(t+1)`을 생성하며(`GE := f_LE(H, P_U) → r^(t+1)`), 별도 모델 `L_follow`가 사용자 참여를 유도하는 후속 질문(suggested follow-ups)을 제안한다.

## 2. GEO 평가 지표: 왜 단순 랭킹이 아니라 'Impression'인가

전통적 검색엔진에서는 페이지 상단부터 1, 2, 3위 링크가 선형으로 나열되므로 평균 순위가 곧 가시성이다. 반면 생성형 엔진에서는 여러 출처가 한 문단 안에 뒤섞여 서로 다른 길이·위치·맥락으로 인용된다.

<figure style="margin: 1.75rem 0; padding: 1rem; background: #ffffff; border: 1px solid var(--border); border-radius: var(--radius);">
  <img src="/images/geo-kdd-2024/figure-3-ranking-vs-visibility.png" alt="Figure 3: 전통 검색엔진의 단순 랭킹과 생성형 엔진의 복합 인라인 인용 가시성 비교" style="width: 100%; height: auto; display: block; border-radius: 6px;" />
  <figcaption style="margin-top: 0.75rem; font-size: 0.88rem; color: var(--text-muted); line-height: 1.55;">
    <strong>Figure 3 (원문 p.4):</strong> 전통 검색엔진(좌)에서는 순위가 곧 가시성이며 크리에이터가 측정·개선 방법을 안다. 반면 생성형 엔진(우)에서는 <code>[1, 3]</code>, <code>[2]</code>, <code>[2, 3]</code>처럼 출처가 교차 합성되어 순위 개념이 사라지므로 새로운 인상(Impression) 지표가 필수적이다.
  </figcaption>
</figure>

저자들은 **① 크리에이터 관련성, ② 설명 가능성, ③ 직관적 이해 가능성**이라는 세 원칙 아래 두 축의 인상 지표(`Imp(cᵢ, r)`)를 설계했다.

### 2.1 객관적 지표: Position-Adjusted Word Count (`Imp_pwc`)
- **Word Count (`Imp_wc`, Eq. 2):** 출처 `cᵢ`를 인용한 문장 집합 `S_ci`의 총 단어 수를 전체 응답 `S_r`의 총 단어 수로 나눈 비율(`Σ |s| / Σ |s_all|`). 한 문장이 여러 출처를 동시에 인용할 경우 해당 문장의 단어 수는 인용된 출처들에 균등 분배한다.
- **Position-Adjusted Word Count (`Imp_pwc`, Eq. 3):** 응답 앞부분에 등장하는 문장일수록 사용자가 읽을 확률이 높다는 점(검색 CTR의 멱법칙 감쇠)을 반영해, 각 문장의 단어 수에 **지수적 위치 감쇠 가중치 `e^(-pos(s)/|S|)`**를 곱한다. 덕분에 길이가 짧더라도 응답 첫머리에 인용된 출처가 후반부에 길게 인용된 출처보다 높은 인상 점수를 받을 수 있다.

### 2.2 주관적 지표: Subjective Impression (G-Eval 기반 7개 차원)
단어 수와 위치만으로는 인용의 질적 영향력을 포착하지 못하므로, **G-Eval** 방식(GPT-3.5 다중 샘플링)으로 아래 7개 세부 차원을 평가한 뒤 `Imp_pwc`와 동일한 평균·분산으로 정규화했다.

| 세부 차원 | 평가 내용 |
| :--- | :--- |
| **1. Relevance (Rel.)** | 인용된 문장이 사용자 질의와 얼마나 직접적으로 관련되는가 |
| **2. Influence (Infl.)** | 생성된 답변 전체가 해당 출처에 얼마나 크게 의존하는가 |
| **3. Uniqueness (Unique)** | 다른 출처와 구별되는 고유한 정보를 제공하는가 |
| **4. Diversity (Div.)** | 답변에 다양한 관점과 맥락을 보태는가 |
| **5. Follow-up (FollowUp)** | 사용자가 해당 인용 링크를 클릭해 추가 탐색할 가능성 |
| **6. Subjective Position (Pos.)** | 사용자 관점에서 인용이 얼마나 눈에 띄는 위치에 있는가 |
| **7. Subjective Count (Count)** | 사용자 체감상 해당 출처에서 가져온 분량이 얼마나 되는가 |

### 2.3 상대적 개선율 계산 (Eq. 4)
한 응답 내 모든 출처의 인상 점수 합이 `1`이 되도록 정규화한 뒤, 특정 출처 `sᵢ`에 GEO를 적용하기 전 응답 `r`과 적용 후 응답 `r'`의 상대적 변화율을 계산한다.
- `Improvement(sᵢ) = ((Imp_si(r') − Imp_si(r)) / Imp_si(r)) × 100`

## 3. 실험 설계: 평가 엔진, GEO-bench, 9가지 최적화 기법

### 3.1 평가 생성형 엔진 및 프롬프트 (Section 3.1 & Listing 1)
- **2단계 구조:** Google 검색 상위 **5개 웹 문서**의 정제된 전문을 추출하고(요약 생략), `gpt-3.5-turbo`(`temperature = 0.7`, 분산 축소를 위해 쿼리당 5개 응답 샘플링)로 답변을 생성했다.
- **시스템 프롬프트(Listing 1):** *"제공된 검색 결과만을 사용해 정확하고 간결하며 편향 없는 저널리즘 어조로 전문가 수준의 답변을 작성하되, 모든 문장 직후에 `[1][2]` 형식의 인라인 인용을 반드시 부착하라"*는 엄격한 근거 기반 지침을 적용했다.

### 3.2 벤치마크: GEO-bench (10,000개 쿼리)
실제 검색 쿼리와 추론·종합이 필요한 복합 쿼리를 모두 포괄하기 위해 **9개 데이터셋**에서 총 10,000개 쿼리(Train 8,000 / Val 1,000 / Test 1,000)를 구축했다. 실제 검색 분포를 반영해 **정보형(Informational) 80%, 거래형(Transactional) 10%, 탐색형(Navigational) 10%** 비율을 유지했으며, 25개 도메인에 걸쳐 GPT-4로 **7개 분류 차원**(난이도, 질의 성격, 장르, 세부 주제, 민감도, 사용자 의도, 답변 유형)을 태깅하고 테스트셋을 수작업 검증했다.

### 3.3 평가 대상 9가지 GEO 기법
각 쿼리의 상위 5개 문서 중 무작위로 1개 문서를 고정 선택해 LLM(`gpt-3.5-turbo`)으로 아래 9가지 변형을 각각 적용하고, 5개 랜덤 시드 평균을 측정했다.

- **기존 콘텐츠 표현 개선형 (추가 외부 정보 불필요):** `Authoritative`(권위적·설득적 어조), `Easy-to-Understand`(쉬운 언어), `Fluency Optimization`(문장 흐름·가독성 개선), `Unique Words`(고유 어휘 추가), `Technical Terms`(전문 용어 보강), `Statistics Addition`(정성 서술을 정량 수치·통계로 전환)
- **외부 근거·키워드 추가형:** `Cite Sources`(신뢰할 수 있는 출처 인용 추가), `Quotation Addition`(권위자·관련 출처의 직접 인용문 추가), `Keyword Stuffing`(전통 SEO 대조군: 질의 키워드 반복 삽입)

## 7. 선행 연구 대비 위치와 논문의 한계

### 7.1 선행 연구와의 차별점 (Section 7)
- **증거 기반 답변 생성 & RAG:** WebGPT(Nakano et al., 2021), REALM, BlenderBot 3, LaMDA 등 기존 연구가 검색 증강 답변 생성 자체에 초점을 맞췄다면, 본 논문은 이를 멀티모달·질의 재작성·출처 선택을 포괄하는 GE 프레임워크로 통합하고 **콘텐츠 제공자 관점의 최적화**를 최초로 정식화했다.
- **비적대적(Non-Adversarial) 최적화:** 프롬프트 인젝션이나 적대적 문자열로 상품 추천을 조작하려 한 Kumar & Lakkaraju (2024)와 달리, GEO는 출처·통계·인용·가독성 개선 등 **정상적이고 비적대적인 텍스트 품질 향상**에 집중한다.

### 7.2 저자가 명시한 4가지 한계 (Section 9)
1. **생성형 엔진의 빠른 진화:** SEO가 지난 25년간 검색 알고리즘 변화에 맞춰 진화했듯, 두 개의 엔진에서 검증된 GEO 기법 역시 향후 GE 아키텍처 변화에 따라 지속적으로 적응해야 한다.
2. **벤치마크 쿼리 분포의 시의성:** `GEO-bench`가 실제 쿼리 분포를 반영하도록 설계되었으나, 사용자 검색 행태 변화에 따라 지속적인 데이터셋 갱신이 필요하다.
3. **기존 검색엔진(SERP) 순위 영향 미검증:** 검색엔진의 블랙박스 특성상 GEO 수정이 전통적 Google 검색 순위에 미치는 영향은 직접 측정하지 않았다. 다만 GEO는 도메인·백링크 같은 오프페이지 요소가 아니라 본문 텍스트만 정교하게 다듬으므로 기존 SEO 순위를 해칠 가능성은 낮으며, 향후 LLM 컨텍스트 길이가 커져 더 많은 후보 문서를 수용하게 되면 초기 검색 순위의 영향력 자체도 줄어들 것으로 전망했다.
4. **자동 태깅 노이즈:** `GEO-bench`의 7개 차원 카테고리를 GPT-4로 자동 태깅하고 테스트셋을 수작업 점검했으나, 주관적 해석 차이에 따른 일부 라벨링 노이즈가 남아 있을 수 있다.
