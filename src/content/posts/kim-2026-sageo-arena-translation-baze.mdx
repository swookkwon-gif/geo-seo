## 초록

검색 증강 생성 엔진(Search-Augmented Generative Engines, SAGE)은 웹 규모의 검색과 생성 기능을 결합해 종합적인 답변을 제공하는 새로운 정보 접근 패러다임으로 등장했다. 이러한 변화는 웹 콘텐츠가 온라인에서 노출되는 방식을 근본적으로 바꾸었으며, AI 생성 응답에서의 가시성을 높이기 위해 웹 문서를 최적화하는 검색 증강 생성 엔진 최적화(Search-Augmented Generative Engine Optimization, SAGEO)의 등장으로 이어졌다. 관심이 커지고 있음에도 현재 SAGEO를 종합적으로 연구할 수 있는 평가 환경은 없다. 기존 벤치마크는 미리 정해진 후보 문서를 사용하고 SAGE의 검색 및 재순위화 단계를 평가 범위에서 제외하므로, 최적화 전략이 가시성에 미치는 영향을 종단 간 평가하지 못한다. 또한 실제 웹 문서에 포함된 구조 정보(예: 스키마 마크업)를 제거하여, 실제 검색 시스템이 적극적으로 활용하는 풍부한 신호를 간과한다. 이러한 공백을 해소하기 위해 단계별 SAGEO 분석을 위한 현실적이고 재현 가능한 환경인 SAGEO Arena를 제안한다. SAGEO Arena는 풍부한 구조 정보를 갖춘 대규모 웹 문서 코퍼스에 전체 생성형 검색 파이프라인을 통합하여, 최적화 신호가 검색에서 생성까지 어떻게 전달되는지 최초로 실증 분석할 수 있게 한다. 분석 결과, 기존 접근법은 실용성이 대체로 낮으며 검색 및 재순위화 단계의 가시성을 떨어뜨리는 경우가 많았다. 구조 정보를 활용하면 이러한 한계를 완화할 수 있지만, 효과적인 SAGEO를 위해서는 파이프라인의 각 단계에 맞춰 최적화해야 한다. 종합하면, 본 벤치마크는 SAGEO 발전을 위한 실용적 기반을 제공한다.

## 1 서론

대규모 언어 모델(Large Language Models, LLMs)이 빠르게 발전하면서 검색 증강 생성 엔진(SAGE) [4, 22, 23, 49]이 새로운 정보 접근 패러다임으로 등장했다. 이러한 시스템은 대규모 검색과 생성 기능을 통합하여, 사용자 질의에 직접 답하는 종합적인 응답을 제공하는 생성형 검색을 수행한다. 이제 이러한 AI 생성 답변에서 유입되는 웹 트래픽의 비중이 늘어나면서 [8], 콘텐츠가 온라인에서 노출되는 방식이 근본적으로 달라지고 있다. 이러한 변화로 인해 AI 생성 응답에서 웹 문서의 가시성(즉, 등장 여부와 기여도)을 높이기 위해 문서를 최적화하는 검색 증강 생성 엔진 최적화(SAGEO)가 등장했다.

SAGEO는 전통적인 검색 엔진 최적화(Search Engine Optimization, SEO) [18]의 핵심 목표를 자연스럽게 확장한다. 수십 년 동안 최적화는 주로 제목과 메타데이터 같은 페이지 내 요소를 통해 검색 엔진 결과 페이지(Search Engine Results Pages, SERPs)에서의 검색 및 순위 성과를 개선하는 데 초점을 맞춰 왔다 [43]. SAGE의 등장과 함께 최적화는 문서가 모델 응답에서 어떻게 우선적으로 선택되고 인용되는지를 연구하는 생성 중심 관점으로 점차 이동했다 [7]. 대표적인 연구 분야인 생성 엔진 최적화(Generative Engine Optimization, GEO) [1]는 생성 단계에서 가시성을 높이기 위해 콘텐츠의 표현 방식을 수정하는 데 초점을 맞춘다. 이러한 변화에도 불구하고 생성형 검색은 흔히 전통적인 검색 시스템을 기반으로 한다. 예를 들어,

MS Copilot은 응답의 근거를 확보하기 위해 Bing Search를 사용한다 [35]. 이는 문서가 LLM의 컨텍스트에 들어가려면 먼저 기반 검색 파이프라인의 결과에 노출되어야 한다는 뜻이다. 따라서 성공적인 최적화를 위해서는 SEO와 GEO를 함께 고려해야 한다. 이에 본 연구는 SAGEO를 검색과 재순위화에서 생성에 이르는 전체 생성형 검색 파이프라인을 대상으로 하는 최적화로 명확히 구분한다(Figure 1). 이는 무엇이 효과적인 SAGEO를 이루며 최적화 신호가 생성형 검색의 여러 단계에 걸쳐 어떻게 전달되고 상호작용하는지를 체계적으로 연구할 필요성을 제기한다.

관심이 커지고 있음에도 이러한 연구를 수행할 수 있는 평가 환경은 없다. 기존 벤치마크 [1, 9, 38, 50]는 실제 웹 환경을 지나치게 단순화하는 경향이 있어, 현재의 최적화 전략이 실무 환경에서도 효과적인지는 불분명하다. 구체적으로 두 가지 주요 한계가 있다. (1) **종단 간 평가의 부재.** 현재 벤치마크는 대부분 미리 정해진 후보 문서를 사용하며, 생성에 앞서 이루어지는 검색 및 재순위화 단계를 평가 범위에서 제외한다. 현재의 최적화 전략이 앞선 검색 단계의 성능을 희생시키는지 아니면 개선하는지가 불분명하므로, SAGEO를 단계별로 분석하는 것이 필수적이다. (2) **구조 정보의 손실.** 기존 벤치마크는 일반 본문 텍스트만 사용하고, 실제 웹 문서에 포함된 구조 정보(예: 스키마 마크업)는 제거한다. 실제 검색 시스템은 본문 텍스트만으로 가시성을 결정하지 않는다. 구조 정보는 검색 단계의 가시성에서 여전히 중요한 역할을 하며, 마크다운 요약과 같은 유사한 구조화 표현도 생성 단계의 가시성을 높이는 것으로 나타났다 [38]. 그러나 구조 정보를 보존하는 기존 벤치마크는 없어, 이러한 정보가 생성형 검색 파이프라인 전반에 미치는 영향은 거의 연구되지 않았다.

이러한 공백을 해소하기 위해 단계별 SAGEO 분석을 지원하도록 설계된 현실적이고 재현 가능한 벤치마크인 SAGEO Arena를 제안한다. 본 벤치마크는 특히 두 가지 측면에서 차별화된다. (1) **포괄적인 생성형 검색 환경.** 고정된 검색 컨텍스트를 가정하는 기존 벤치마크와 달리, SAGEO Arena는 문서를 동적으로 검색하고 순위를 매긴 뒤 생성 단계로 전달하는 전체 생성형 검색 파이프라인을 통합한다. 각 단계는 모듈화되어 있고 설정을 변경할 수 있으므로, 연구자는 최적화 신호가 전체 검색 과정에서 어떻게 전달되는지 추적할 수 있다. (2) **풍부한 구조 주석을 갖춘 대규모 코퍼스.** 본 연구는 9개 도메인에 걸친 170k개의 웹 문서로 코퍼스를 구축한다. 상용 검색 엔진이 공개한 지침에 따라 본문 텍스트와 함께 실제 SAGEO에서 고려해야 할 풍부한 구조 정보(예: 메타 설명, 표제, 스키마 마크업)를 추출한다. 종합적으로 본 연구는 실제 배포 환경을 충실히 반영하는 환경을 구축하여, 통제된 실험 조건을 넘어 일반화할 수 있는 최적화 전략의 기반을 마련하고자 한다.

본 연구는 SAGEO Arena에서 광범위한 실험을 수행하여 최적화 전략이 전체 생성형 검색 파이프라인의 문서 가시성에 미치는 영향을 평가한다. 분석 결과, 선행 연구가 주로 다뤄 온 본문 텍스트만의 최적화는 현실적인 생성형 검색 환경에서 대체로 충분하지 않다. 이 방식은 생성 단계의 가시성을 소폭 개선하는 데 그치며, 더 중요하게는 검색 성능을 저하시켜 최적화된 문서가 검색 결과에서 누락되게 한다. 반면 구조 정보는 파이프라인 초기 단계의 문서 가시성을 뒷받침하는 신호를 보존하여 이러한 저하를 완화한다. 또한 두 최적화 범위가 근본적으로 상호 보완적인 역할을 한다는 점을 확인했다. 구조 정보는 검색을 좌우하며, 정보가 충실한 본문 텍스트는 재순위화와 생성에서 여전히 핵심 요소다. 도메인, 인용 행태, 최적화 모델에 대한 심층 분석을 통해 파이프라인의 각 단계가 서로 다른 문서 특성을 우선시한다는 점도 보여 주며, 이는 단계별 특성을 고려한 최적화의 필요성을 뒷받침한다. 이러한 결과를 바탕으로 각 단계에 맞게 최적화 전략을 조정하는 단계 인식형 SAGEO를 제안한다. 이 방법은 평가한 모든 전략 중 전반적인 가시성 향상 폭이 가장 컸다. 본 연구의 기여를 요약하면 다음과 같다.

- SAGEO의 가시성을 단계별로 평가할 수 있는 최초의 벤치마크인 SAGEO Arena를 제안한다. SAGEO Arena는 전체 생성형 검색 파이프라인을 풍부한 구조 정보를 보존한 대규모 코퍼스와 통합하여, 기존 벤치마크와 실제 SAGE 사이의 간극을 좁힌다.
- 구조 정보 최적화에 대한 최초의 실증 분석을 제공하고, 실제 생성형 검색 시스템이 처리해야 하는 구조 신호가 가시성에 어떤 영향을 미치는지 살펴본다.
- 광범위한 실험을 통해 현재의 최적화 접근법이 현실적인 환경에서는 충분하지 않음을 보여 준다. 이를 해결하기 위해 단계 인식형 SAGEO를 제안하고, 후속 SAGEO 연구를 촉진할 수 있는 실행 가능한 지침을 제공한다.

## 2 관련 연구

### 2.1 생성형 검색 엔진 최적화

LLM의 등장과 함께 생성형 검색 [6, 20, 31, 56]은 현대 정보 접근의 핵심으로 자리 잡았으며, 검색된 문서를 근거로 종합적인 답변을 제공한다. 이러한 변화는 콘텐츠 제작자에게 새로운 가시성 과제를 제기하며, 생성 엔진에 특화된 최적화 전략 연구를 촉진했다. 기존 연구는 크게 두 방향으로 나눌 수 있다. (1) 블랙햇 접근법은 악성 콘텐츠 삽입을 통해 모델의 동작을 악용하는 적대적 방법을 탐구한다 [24, 36, 37]. 이와 대조적으로 (2) 화이트햇 접근법은 협력적인 콘텐츠 수정에 초점을 맞추며, 이는 GEO로 정식화되었다 [1]. 이를 토대로 후속 연구 [9, 38, 50]는 다양한 최적화 전략과 평가 차원을 제안하여 GEO 연구를 발전시켰다(Table 1). 그럼에도 기존 평가 절차는 지나치게 단순화된 환경에 의존하는 경우가 많으며, 주로 고정된 후보 문서를 사용해 생성 단계에서의 최적화 효과를 평가한다. 다시 말해, 최적화 이후에도 대상 문서가 LLM의 컨텍스트 안에 남아 있다고 가정할 뿐, 최적화된 문서가 여전히 검색과 재순위화를 거쳐 해당 컨텍스트에 포함될 수 있는지는 검증하지 않는다. 따라서 최적화 신호가 전체 생성 파이프라인을 거치며 어떻게 전달되는지는 거의 탐구되지 않았다. 이를 바탕으로 본 연구는 생성형 검색 파이프라인을 종단 간 명시적으로 모델링하는 종합적인 평가 환경을 제공한다.

### 2.2 SEO와 GEO의 비교

전통적인 SEO는 오랫동안 온라인 가시성을 확보하는 주된 틀로 활용되어 왔으며 [17, 26, 39, 43], 정보 출처가 SERP에서 더 높은 순위에 오르도록 하는 것을 목표로 한다. 주요 검색 엔진 제공업체가 제시한 지침 [14, 34]에 따라 SEO는 오랫동안 제목, 메타 설명, 표제, 스키마 마크업 등 페이지의 해석과 노출을 돕는 구조 정보를 강조해 왔다. 이와 달리 GEO 연구는 주로 생성 단계에서 본문 텍스트를 수정하는 데 초점을 맞추며 [10], 유창성, 전문성, 이해 용이성 등의 텍스트 특성을 조정하는 재작성 전략을 연구한다. 그러나 최근의 실증 결과 [38]는 검색과 재순위화 단계에서 결정된 문서의 위치가 최종 응답에서의 가시성을 좌우하는 데 훨씬 더 큰 역할을 한다는 사실을 보여 주며, 이러한 생성 중심 관점에 의문을 제기한다. 특히 문서의 위치는 전통적인 SEO에서 강조하는 구조 정보에 의해 좌우되는 경우가 많으며, 이는 다음과 같은 근본적인 질문을 제기한다. 이러한 신호가 생성 엔진에서의 가시성에도 기여하는가? 기존 벤치마크가 이 질문에 제공하는 통찰은 제한적이며, 본 연구는 전체 생성형 검색 파이프라인에서 SEO와 GEO 신호가 어떻게 상호작용하는지를 함께 분석하여 이 공백을 메운다.

### 2.3 구조화된 웹 정보의 이해

월드 와이드 웹은 근본적으로 하이퍼텍스트 마크업 언어(HyperText Markup Language, HTML)를 기반으로 구축되어 있다. HTML 문서는 본문 콘텐츠 외에도 제목 태그, 메타 설명, 표제 계층, 스키마 마크업 등의 요소를 통해 구조 정보를 담는다. 이러한 구조적 속성은 오랫동안 검색 엔진이 문서를 크롤링하고 색인하며 순위를 매기는 방식에 영향을 미쳐 왔다 [28]. 최근 연구 [11, 19, 46, 48]는 구조 정보가 LLM의 웹 콘텐츠 이해를 돕는다는 점을 입증하고, HTML의 구조적 표현이 검색 증강 생성(Retrieval-Augmented Generation, RAG) 시스템에서 일반 텍스트를 보완한다는 사실을 보여 준다. 또한 MS Copilot과 Google Search 같은 상용 SAGE도 웹 문서를 해석하고 노출할 때 마찬가지로 구조 정보를 활용한다는 근거가 있다 [15, 25, 34]. 이러한 결과는 SAGEO 연구에 구조 정보를 포함할 필요성을 뒷받침하지만, 그 영향을 체계적으로 평가하는 기존 벤치마크는 없다. 본 연구는 웹 문서의 구조적 요소를 보존하는 새로운 벤치마크를 제안하여 이 공백을 해소하고, 실제 생성형 검색 환경에서 최적화 전략을 더욱 현실적으로 평가할 수 있게 한다.

## 3 SAGEO Arena

**문제 설정.** 본 연구는 관련 웹 문서를 검색하고 검색된 콘텐츠를 근거로 응답을 종합하여 사용자 질의에 답하는 검색 증강 생성 엔진을 고려한다. 파이프라인은 널리 확립된 RAG 패러다임 [29]을 따르며, 검색기, 재순위화기, 생성기로 구성된다. 이 환경에서 문서가 생성된 응답에 영향을 미치려면 먼저 검색되고 순위가 매겨져야 한다. 이로 인해 전통적인 SEO의 관심사(검색과 순위화)와 새롭게 부상한 GEO의 관심사(생성) 사이에는 본질적인 의존 관계가 생긴다. 본 벤치마크는 이 전체 파이프라인을 반영하도록 설계되어, 세 단계 모두에서 최적화 전략을 면밀히 평가할 수 있다.

**설계 원칙.** 핵심 과제는 실제 검색 증강 생성 엔진을 반영하는 환경을 재현하는 것이다. 이를 위해 (1) 확립된 관행 [13, 16, 40]을 따르는 표준화된 검색 증강 생성 파이프라인을 채택하고, (2) 상용 검색 엔진이 최적화에 활용하도록 명시적으로 권장하는 구조 정보를 보존한다 [14, 33, 34].

### 3.1 코퍼스 구축

도메인 다양성이 높은 대규모 코퍼스를 구축하기 위해, 폭넓은 도메인을 포괄하는 9개의 기존 정보검색 데이터셋에서 질의를 선별한다(Table 6). 각 데이터셋에서 300개의 질의를 표본으로 추출하여 총 2,700개의 고유 질의를 확보한다. 선행 접근법을 따라 Google Custom Search API로 질의당 최대 100개의 검색 결과를 가져온다. 그런 다음 각 URL을 크롤링하여 본문 텍스트와 풍부한 구조 정보를 추출한다(3.2절). 콘텐츠 형식이 올바르지 않은 문서를 걸러낸 뒤, 최종 코퍼스에는 171,003개의 고유 웹 문서가 포함된다. 각 질의에는 평균 63개의 후보 문서가 연결된다. 도메인별로 추출한 300개의 질의는 최적화 평가를 위한 테스트 질의로 사용된다. ### 3.2 구조 정보 추출

본문 텍스트만 추출하는 기존 벤치마크와 달리, 본 연구는 실제 웹 문서에 내장된 구조 정보를 명시적으로 보존한다. 그러나 이러한 문서는 다양성이 매우 크고 잡음이 많아 [47, 54], 체계적인 평가를 위해 모든 구조 정보를 보존하는 것은 현실적이지 않다. 따라서 공개 검색 엔진 지침 [34]에서 일관되게 강조하는 구조 필드를 선별해 보존함으로써, 이러한 요소가 검색 증강 생성 엔진에 미치는 영향을 현실적이면서도 통제된 방식으로 연구할 수 있게 한다.

- **제목.** 문서 제목은 페이지의 주제를 간결하게 요약한다. 제목은 페이지의 주요 주제와 목적을 알려 주는 핵심 신호로서 초기 관련도 평가에서 중요한 역할을 한다.
- **메타 설명.** 검색 결과의 스니펫에 사용하기 위한 간결한 페이지 요약이다. 이 필드는 페이지의 내용을 짧지만 유용하게 설명하여 제목을 보완한다.
- **표제.** 문서 내 주제 구조를 나타내는 계층적 섹션 제목(H1–H6)이다. 검색 엔진은 표제를 각 섹션의 주제를 알려 주는 강한 지표로 취급하며, 주변 본문 텍스트보다 높은 가중치를 부여하는 경우가 많다.
- **스키마/JSON-LD.** 개체, 속성, 관계를 기계가 읽을 수 있는 형식으로 명시적으로 정의하는 구조화 데이터 마크업이다. 검색 엔진은 일반 텍스트만으로는 추론할 수 없는 페이지의 의미를 해석하기 위해 이 마크업을 활용한다.
- **본문 텍스트.** 문서의 주요 텍스트 콘텐츠이며, 일차적인 정보 출처다.

특히 색인 단계에서 이 필드들을 하나의 텍스트 표현으로 합치면 각 구성 요소가 전달하는 고유한 신호가 흐려진다. 따라서 검색 증강 생성 엔진은 일반적으로 이 필드들을 별도의 구성 요소로 색인하고, 이후 관련도 점수를 산정할 때 결합한다 [42]. 본 연구도 같은 방식을 채택하여 필드 간 구분을 유지하고, 각 구성 요소가 파이프라인 전반의 가시성에 어떻게 기여하는지 세밀하게 분석할 수 있게 한다.

### 3.3 검색 증강 생성 엔진

본 연구는 검색, 재순위화, 생성으로 구성된 전체 생성형 검색 엔진 파이프라인을 구현한다. 각 단계는 실제 운영 관행을 반영하면서도 통제된 실험이 가능하도록 모듈화되어 있다.

**문서 표현.** 본 연구의 설정에서 웹 문서는 구조 정보와 본문 텍스트라는 두 유형의 콘텐츠로 구성된다. `S(𝑑) = {𝑠₁, …, 𝑠ₘ}`으로 표기하는 문서의 구조 정보는 3.2절에서 설명한 요소(예: 제목, 메타 설명)에 해당하는 구조 필드의 집합이다.

`P(𝑑) = {𝑝₁, …, 𝑝ₙ}`으로 표기하는 문서의 본문 텍스트는 표준 관행에 따라 본문을 분할해 얻은 구절의 집합이다. 따라서 문서는 `(S(𝑑), P(𝑑))`로 표현할 수 있다.

**의미 단위.** 생성형 검색 시스템에서는 문서를 구절 단위로 분할하고 검색하는 경우가 많다. 그러나 웹 문서의 구조 정보는 모든 구절에 공통으로 적용되므로, 효과적으로 검색하려면 문서 수준 정보와 구절 수준 정보 사이의 간극을 해소해야 한다. 따라서 각 구절 `𝑝ᵢ ∈ P(𝑑)`를 해당 구조 정보 `S(𝑑)`와 짝지어 의미 단위 `U(𝑝ᵢ) = S(𝑑) ∪ {𝑝ᵢ}`를 구성하고, 검색 및 재순위화에서 이를 `𝑝ᵢ`의 구절 표현으로 사용한다.

**검색기.** 본 연구는 널리 사용되는 어휘 기반 검색 방식인 BM25 [41]를 검색기 `R`로 사용한다. 이는 웹 규모 검색 시스템에서 어휘 기반 검색이 효율적이고 확장 가능한 1단계 후보 생성기로 쓰이는 실무적 역할을 반영한 선택이다. 각 의미 단위 `U(𝑝)`에 대해 모든 요소 `𝑢 ∈ U(𝑝)`별로 별도의 BM25 색인을 구축한다. 질의 `𝑞`가 주어지면 각 `𝑢`에 대한 `𝑞`의 점수를 독립적으로 산정하고, 그 결과로 얻은 순위들을 역순위 융합으로 통합하여 구절 `𝑝`의 검색 점수를 구한다.

`score_R(𝑞, 𝑝) = ∑_{𝑢 ∈ U(𝑝)} 1 / (𝜅 + rank(𝑞, 𝑢)),` (2)

여기서 `rank(𝑞, 𝑢)`는 요소 `𝑢`의 순위이고, `𝜅`는 상수다. 상위 `𝑘`개 구절을 재순위화 후보로 선택한다.

**재순위화기.** 검색된 후보는 각 질의–구절 쌍 `(𝑞, 𝑝)`의 점수를 독립적으로 산정하는 교차 인코더를 사용해 재순위화한다. 실제 운영 시스템(예: Vespa AI¹, Google Vertex AI²)의 관행을 따라, 문서 전체가 아닌 구절 단위로 관련도 점수를 산정한다. 이 방식은 긴 문서에서 특정 섹션만 질의와 관련된 경우를 처리할 수 있다.

**생성기.** 재순위화에서 상위에 오른 후보를 해당 구조 필드와 함께 생성 모델에 제공한다. 모델에 출처를 인용하도록 지시하여 문서 단위의 가시성을 측정할 수 있게 한다.

SAGEO Arena는 구조 정보가 보강된 문서를 사용하는 전체 파이프라인을 기반으로 설계되어, 기존 벤치마크의 범위를 넘어서는 분석을 지원한다. 구체적으로 (1) 다양한 전략의 단계별 평가, (2) 구성 요소 단위의 제거 실험, (3) 현실적인 여러 환경에서의 강건성과 일반화 성능 검증이 가능하다.

### 3.4 단계별 가시성 평가

SAGEO Arena가 파이프라인의 각 단계에서 문서 가시성을 측정하고 최적화 효과를 정량화하는 방법을 설명한다.

**평가 파이프라인.** Figure 2에서 보듯, 기준선은 다음과 같이 설정한다. 각 테스트 질의 `𝑞`에 대해 먼저 SAGEO Arena의 전체 생성형 검색 파이프라인을 실행한다. 생성 단계에 도달한 문서, 즉 재순위화 단계에서 상위 `𝑘`위 이내에 든 문서 가운데 하나를 무작위로 대상 문서 `𝑑_tgt`로 선택하여 기준선 인스턴스 `(𝑞, 𝑑_tgt)`를 구성한다. 그런 다음 지정된 전략으로 대상 문서 `𝑑_tgt`를 최적화하고 3.3절에 설명한 절차에 따라 코퍼스에 다시 색인한다. 이후 동일한 질의로 검색 파이프라인을 다시 실행하고 각 단계에서 문서 가시성을 기준선과 비교한다. 이를 통해 기존 벤치마크처럼 고정된 검색 컨텍스트 내에서가 아니라,

현실적인 조건에서 단계별 최적화 효과를 평가할 수 있다.

**대상 문서 추적.** 검색 증강 생성 엔진은 내부적으로 구절 단위로 동작하므로, 각 구절의 점수가 독립적으로 산정되어 동일한 문서의 여러 구절이 후보 목록에 나타날 수 있다. 따라서 대상 문서의 가시성을 추적하는 데에는 본질적인 어려움이 따른다. 이를 해결하기 위해 파이프라인의 각 단계에서 대상 문서 `𝑑_q^tgt`의 순위를 해당 문서에 속한 구절 중 가장 높은 순위로 정의한다.

`rank(𝑑_q^tgt) = min_{𝑝 ∈ P(𝑑_q^tgt)} rank(𝑝),` (3)

여기서 `P(𝑑_q^tgt)`는 `𝑑_q^tgt`에서 추출한 구절의 집합을 나타낸다. 각 단계에서 가장 높은 순위의 구절이 해당 문서의 가시성 지표가 되며, 최적화 효과는 두 가지 방식으로 측정한다. (1) 대상 문서가 각 단계에서 상위 `𝑘`개 후보에 포함되는지, (2) 최적화 전후로 대상 문서의 순위가 어떻게 달라지는지를 측정한다.

**평가 지표.** 각 테스트 질의 `𝑞 ∈ 𝑄`에 대해 파이프라인을 실행하고 식 (3)을 사용하여 해당 대상 문서 `𝑑_q^tgt`의 순위를 추적한다. 그런 다음 두 가지 상호 보완적인 지표로 각 단계의 가시성을 평가한다. (1) **적중률(H@𝑘)**은 대상 문서가 상위 `𝑘`개 후보에 포함되는 질의의 비율을 측정한다. 검색 및 재순위화 단계에서는 다음과 같이 정의한다.

`H@𝑘 = (1 / |𝑄|) ∑_{𝑞 ∈ 𝑄} I(rank(𝑑_q^tgt) ≤ 𝑘),` (4)

여기서 `I(·)`는 조건이 충족되면 1을, 그렇지 않으면 0을 반환한다. 생성 단계에서는 대신 최종 응답에 대상 문서가 인용된 질의의 비율인 **인용률**을 사용한다. (2) **순위 변화**는 기준선과 최적화 조건 사이에서 나타나는 대상 문서의 평균 순위 변동이다.

`ΔRank = (1 / |𝑄|) ∑_{𝑞 ∈ 𝑄} (rank_base(𝑑_q^tgt) − rank_SAGEO(𝑑_q^tgt)),` (5)

여기서 `rank_base`와 `rank_SAGEO`는 각각 최적화 전후의 대상 문서 순위를 나타낸다. 검색 또는 재순위화 단계에서 상위 `𝑘`개 후보에 들지 못한 문서에는 기본 순위 `𝑘 + 1`을 부여한다. 검색에는 `𝑘 = 100`, 재순위화에는 `𝑘 = 10`을 설정한다. 생성 단계의 순위는 해당 출처가 응답에서 처음 인용되는 순서로 정의한다.

- **출처 인용(Cite Sources):** 외부 출처에 대한 짧은 참조를 본문 내 인용으로 덧붙여 신뢰성과 믿을 만한 정도를 높인다.
- **유창성(Fluency):** 내용의 의미는 바꾸지 않고 문장 구조와 문장 간 연결을 다듬어 문법적 정확성을 높인다.
- **인용문(Quotation):** 권위 있는 인물이나 출처의 발언 또는 문구를 출처와 함께 인용해 외부 근거를 제공한다.
- **쉬운 표현(Easy Language):** 정보를 보존하면서 어려운 어휘를 이해하기 쉬운 표현으로 바꾸어 텍스트를 쉽게 만든다.
- **통계(Statistics):** 정량적 데이터와 수치로 표현된 사실을 문장 안에 추가하여 주장을 더욱 구체적이고 신뢰할 수 있게 만든다.
- **전문 용어(Technical Terms):** 도메인에 특화된 용어를 도입하여 콘텐츠를 더욱 전문적이고 권위 있게 제시한다.
- **희소 어휘(Unique Words):** 덜 흔한 단어를 사용해 어휘를 풍부하게 만들고 콘텐츠의 높은 품질과 전문성을 드러낸다.
- **All-in-One:** 8가지 기본 전략을 모두 결합한 뒤 핵심 요소를 굵게 표시하고 배치를 개선하여, 정보 접근성과 시각적 매력을 높이도록 텍스트 구조를 보강한다.
- **AutoGEO:** 생성 엔진의 인용 패턴을 분석해 학습한 최적화 규칙을 적용하여 문서 재작성의 방향을 정한다.

### 5.1 주요 결과

SAGEO Arena에서 수행한 광범위한 실험의 결과를 제시한다. 본 연구의 목표는 최적화 전략이 전체 생성형 검색 파이프라인에서 문서 가시성에 어떤 영향을 미치는지 평가하는 것이다. 기존 연구는 SAGE에서 본문 텍스트에만 초점을 맞췄으며, 이러한 설정이 현실적인 환경에서 얼마나 효과적인지는 거의 연구되지 않았다. 또한 검색 시스템이 문서를 올바르게 해석하도록 핵심 문서 정보를 메타데이터 필드로 구성하는 과정인 구조 정보 최적화(3.2절)는 생성형 검색의 맥락에서 연구된 바 없다. 따라서 최적화 범위를 본문 텍스트만, 구조 정보만, 둘 다의 세 가지 설정으로 나누어, 생성형 검색 파이프라인의 각 단계에서 성과의 향상과 저하가 어디에서 비롯되는지 최초로 분석한다.

**본문 텍스트만 최적화할 때의 한계.** Table 2(왼쪽)에 나타난 것처럼 본문 텍스트만 최적화하면 모든 단계에서 일관되게 가시성이 저하된다. 검색 단계에서는 흔한 표현을 도메인에 특화된 용어(예: 전문 용어)나 잘 쓰이지 않는 어휘(예: 희소 어휘)로 바꾸는 최적화 전략에서 검색 성능이 가장 크게 떨어진다. 본 연구는 그 원인을 최적화된 문서와 대체로 일상적인 어휘를 사용하는 사용자 질의 사이의 어휘 불일치로 본다. 예를 들어 “eating”(먹기)을 “alimentary routines”(섭식 일과)로 바꾸거나 “sleeping”(잠자기)을 “somnolence”(졸림)로 바꾸면 일치하는 용어가 직접적으로 줄어들어, BM25 기반 검색기가 더 낮은 관련도 점수를 부여하게 된다. 특히 AutoGEO [50]에서 성능 저하가 가장 컸으며, 검색 순위 변화는 −22.35였다. 분석 결과, AutoGEO는 문서 내용을 크게 늘리는 경향이 있으며, 재작성된 텍스트가 길어지면서 키워드 밀도가 낮아지고 문서의 어휘도 원래 질의의 어휘에서 더욱 멀어진다. 재순위화에서도 유사하지만 더 완만한 성능 저하가 관찰되었는데, 이는 재작성 과정에서 재순위화기가 민감하게 반응하는 미세한 의미 변화가 생길 수 있음을 시사한다. 그러나 평균 순위 하락 폭이 작더라도 검색이나 재순위화 단계의 작은 순위 변동은 실제로 중대한 영향을 미칠 수 있다. 생성형 검색에서는 상위 문서만 생성기에 전달되므로, 이 기준에 미달하는 문서는 완전히 제외되어 콘텐츠 품질과 무관하게 생성 단계에서 노출되지 않는다. 생성 단계에서는 전략 전반에 걸쳐 개선 폭이 비교적 작으며, 이는 표현 방식의 수정으로 얻을 수 있는 가시성 향상이 제한적이라는 최근 연구 결과 [38]와 일치한다. 종합하면 본문만 최적화하는 것으로는 파이프라인 전체의 가시성을 높이기에 충분하지 않다. 이러한 결과는 효과적인 최적화가 본문 텍스트를 넘어, 실제 생성형 검색 시스템에서 문서 순위 결정에 중요한 역할을 하는 구조 정보까지 포함해야 함을 시사한다.

그림 5: 문서 영역별 인용 출처 밀도.

근거를 제공하기 때문이다. 쇼핑은 모든 최적화 방법이 인용 가능성을 낮추는 유일한 도메인이다. 상품 문서는 대개 이미 고객을 위해 잘 구성되어 있으며, 이 도메인의 질의는 주로 일상적인 표현으로 추천을 구하는 형태이다(예: “친구에게 줄 선물 아이디어”). 이러한 문서를 최적화하면 독자가 기대하는 어조에서 벗어나 생성기의 응답에 포함되기 위한 경쟁력이 떨어질 수 있다. 이 결과는 도메인별 사용자 의도를 고려하지 않고 적용한 최적화 전략이 효과가 없거나 오히려 해로울 수 있음을 시사하며, 도메인을 고려한 최적화의 필요성을 강조한다.

**인용 출처 분석.** 생성 단계에서 인용을 이끄는 요인을 파악하기 위해, 생성 모델이 응답을 구성할 때 문서 콘텐츠를 어떻게 활용하는지 살펴본다. 이를 위해 생성기에 응답 내 각 인용에 사용한 구절을 원문 그대로 제시하도록 요청하는 실험을 수행한다. 그런 다음 퍼지 매칭을 적용하여 각 인용 구절을 출처 문서에서 찾아내고, 어느 영역에서 가져왔는지 식별한다. 그림 5는 결과를 밀도 그래프로 보여 준다. 색으로 구분된 각 영역은 구조적 구성 요소(예: 제목, 메타 설명, 표제, JSON-LD) 또는 본문에 해당하며, 수평 기준선(`𝑦 = 1.0`)을 넘는 값은 해당 영역이 더 자주 인용되는 경향이 있음을 나타낸다. 인용의 압도적 다수는 본문에서 비롯되며, 구조 정보는 검색에 크게 기여함에도 인용 빈도가 낮다. 이는 본문의 정보 밀도가 높아, 간결하고 키워드 중심적인 구조 정보보다 사용자 질의에 답할 수 있는 근거를 더 풍부하게 제공하기 때문으로 본다. 구조 정보가 생성 단계의 가시성을 높인다는 앞선 결과(5.1절)와 종합하면, 구조 정보는 문서가 노출되는 데 중요한 역할을 하지만 생성기는 응답을 구성할 때 주로 본문을 참조한다는 점을 알 수 있다. 따라서 SAGE에서 구조 정보와 본문은 상호 보완적인 역할을 하며, 효과적인 최적화를 위해서는 둘 다 다루어야 한다.

**실용 지침.** 이를 위해 파이프라인의 각 단계에서 중시하는 요소에 맞춰 최적화를 조정하는 단계 인식 최적화를 제안한다. 제안 방법은 다음 원칙을 바탕으로 한다.

- **핵심 개체로 구조 필드를 보강한다.** 본문의 핵심 개체, 수치, 용어를 구조 필드에 정리하여 검색 단계에서 질의와 문서 간의 일치도를 높인다.
- **주장을 눈에 잘 띄게 하고 그 자체로 이해할 수 있게 한다.** 핵심 주장을 본문 첫머리에 배치하고 각 진술에 구체적인 근거를 포함하여, 생성 단계에서 인용될 가능성을 높인다.
- **문단 간 주제 일관성을 유지한다.** 지시 대상이 모호한 대명사는 해당 대상을 명시하는 표현으로 바꾸고, 핵심 용어를 자연스럽게 강조하여 문단들이 서로 연결되도록 한다.
- **도메인 맥락에 맞춘다.** 수정에 앞서 문서의 도메인을 파악하고, 도메인의 특성과 사용자 의도를 모두 고려하여 최적화 방식을 결정한다.

표 3은 제안 방법의 효과를 보여 준다. 제안 방법은 모든 단계에서 경쟁력 있는 성능을 달성하며, 평가한 전략 가운데 재순위화와 생성 두 단계 모두에서 두드러진 개선을 보인다. 이 결과는 SAGEO Arena가 단계별 분석을 가능하게 하고 실행에 옮길 수 있는 시사점을 제공함으로써 실용적인 SAGEO 방법을 개발하는 데 효과적인 평가 환경임을 시사한다. 제안 방법에 사용한 상세 프롬프트는 부록 E에 제시한다.

## 6 결론

본 논문에서는 검색 증강 생성형 엔진 최적화의 단계별 가시성을 분석하기 위한 현실적인 평가 환경인 SAGEO Arena를 소개한다. SAGEO Arena는 전체 생성형 검색 파이프라인을 구조 정보를 보존한 대규모 말뭉치와 통합하여, 생성형 검색에서 최적화 신호가 각 단계에 어떻게 전달되는지 연구할 수 있게 한다. 기존 벤치마크에서 얻은 결과는 현실적인 환경에 쉽게 일반화되지 않으며, 파이프라인의 각 단계를 겨냥한 단계 인식 최적화가 생성형 검색에서 가시성을 확보하는 데 중요하다는 점을 확인했다. 종합하면, SAGEO Arena는 실제 생성형 검색에 일반화할 수 있는 최적화 전략의 개발을 위한 재현 가능한 환경을 제공한다.

MS MARCO [2](웹 검색), Natural Questions(일반 질의응답) [27], HotpotQA [53](다중 홉 질의응답), NFCorpus [3](생의학), Quora [44](커뮤니티 질의응답), FiQA [32](금융), DebateQA [52](토론), E-commerce(쇼핑), Researchy(학술) [50]가 이에 해당한다. 도메인은 콘텐츠 특성, 질의 복잡성, 정보 탐색 행동이 다양하도록 선정했다. 상세 통계는 표 6에 제시한다.

**RAG 벤치마크와의 차이.** 표준 RAG 벤치마크는 질의와 문서 말뭉치가 주어졌을 때 시스템이 출처에 충실하고 관련성 높은 답변을 생성하는지를 평가한다. 이 설정은 답변의 품질을 측정하는 데 유용하지만, 특정 문서가 검색, 재순위화, 생성 전반에서 가시성을 유지할 수 있는지가 핵심인 콘텐츠 제작자의 관점을 직접 반영하지는 않는다. SAGEO Arena는 실제 생성형 검색 파이프라인을 근사하고 최적화 전후의 대상 문서 가시성을 측정하여 이 간극을 해소한다. 또한 SAGEO Arena는 웹 문서의 구조 정보를 보존한다. 이러한 필드는 검색 시스템이 웹 문서를 해석하고 노출하는 데 유용한 신호를 제공하지만, 주로 일반 텍스트 형식의 본문 구절을 다루는 RAG 방식의 벤치마크에서는 대개 제외된다.

## B 구현 세부사항

3.3절에서 설명한 파이프라인을 다음과 같이 구성하여 구현한다. 문서 본문을 256토큰 길이의 구절로 나누되, 인접 구절 간에 64토큰이 겹치도록 한다. 색인 과정에서는 통제되고 공정한 기준선을 마련하기 위해 구조 필드와 분할한 구절에 동일한 가중치를 부여한다. 실제 검색 엔진에서는 필드마다 서로 다른 가중치를 부여하지만 [12], 동일한 가중치를 적용하면 관찰된 가시성 변화가 필드별 편향이 아니라 최적화 전략에서 비롯되도록 할 수 있다. 질의마다 상위 100개 구절을 검색한 뒤 Qwen3-Reranker-4B [55]로 점수를 다시 산정한다. 생성 단계에서는 응답을 종합하기 위해 상위 10개 후보를 남겨 두고 GPT-5-mini를 기본 생성 모델로 사용한다. 각 테스트 질의에 대해 먼저 전체 검색 파이프라인에 질의를 실행하여 기준선을 설정한 뒤, 생성 단계에 진입하는 상위 10개 후보(즉 재순위화 후 10위 이내에 든 후보)에서 대상 문서를 무작위로 선택하여 테스트 질의와 충분한 관련성을 확보한다. 모든 SAGEO 최적화 전략은 GPT-5-mini와 전략별 프롬프트를 사용하여 구현하며, 8가지 콘텐츠 수정 전략에는 [1]을, All-in-One에는 [38]을, AutoGEO에는 [50]을 따른다.

## C 추가 분석

**최적화 전략은 질의 표현 변화에 대한 견고성이 제한적이다.** 실제 사용자는 다양한 질의 표현으로 정보 요구를 나타내므로, 효과적인 최적화를 위해서는 질의 변형에 대한 견고성이 필수적이다. 이를 살펴보기 위해 확장(구체성 추가), 단순화(핵심 키워드 유지), 바꿔 쓰기(어휘 대체), 추상화(의미적 일반화)라는 네 가지 질의 재작성 전략을 적용하여 최적화된 문서를 평가한다. 그림 7에는 [1]의 8가지 최적화 전략에 걸쳐 평균한 결과를 제시한다. 모든 질의 변형에서 일관된 가시성 저하가 나타나며, 원래 표현에서 벗어날수록 가시성이 더 떨어진다. 입력 질의를 모르는 상태에서 문서를 최적화하기 때문에 문서의 기존 내용을 더 상세히 서술하는 경향이 있으며, 그 결과 문서는 원래의 주제와 어휘에 더욱 특화된다. 따라서 최적화 효과는 질의 표현에 민감해지며, 특히 재작성된 질의와 최적화된 문서 사이의 어휘 중복이 줄어들 때 이러한 민감성이 두드러진다. 예를 들어 추상화에서는 질의가 문서의 원래 표현을 넘어 일반화되므로 가시성 저하가 가장 뚜렷하며 하락 폭도 가장 크다. 이 결과는 기존 전략을 다른 질의 표현에 적용하는 데 한계가 있음을 보여 주며, 다양한 질의 표현에서도 가시성을 유지하는 견고한 SAGEO 방법이 필요함을 뒷받침한다.

그림 7: 세 가지 최적화 범위에서 네 가지 질의 변형에 따른 파이프라인 단계별 문서 가시성. 표시된 값은 8가지 최적화 전략에 걸쳐 평균한 것으로, 검색 및 재순위화 단계에서는 평균 적중률을, 생성 단계에서는 평균 인용률을 나타낸다. 빨간색 숫자는 원래 질의와 성능이 가장 낮은 변형 간의 변화 폭을 퍼센트포인트로 나타낸다.

**답변 품질 분석.** 본 연구의 주된 초점은 문서 가시성 평가이지만, SAGEO가 답변 품질에 미치는 영향도 추가로 분석한다. SAGEO Arena는 적대적 신호를 삽입하는 대신 콘텐츠를 협력적으로 개선하는 화이트햇 문서 최적화를 연구한다. 또한 생성된 각 답변은 검색된 여러 문서를 근거로 삼으므로, 대상 문서 하나를 수정하는 것만으로는 전반적인 답변 품질이 유의미하게 달라질 가능성이 작다. 이를 실증적으로 검증하기 위해 최적화 전후를 비교하는 표본 3,000개로 기본 검증을 수행하고, GPT-5.4를 평가 모델로 사용해 생성된 답변이 질의의 정보 요구를 충족하는지 평가한다. 전체 방법을 종합했을 때 최적화 후 수치는 88.9%에서 87.3%로 소폭 변하는 데 그쳤다.

## D 한계

SAGEO Arena는 실무에 적용할 수 있는 시사점을 제공하기 위해 현실적인 생성형 검색 파이프라인을 근사하지만, 독자적인 순위 신호나 사용자 행동 신호를 사용하는 상용 검색 엔진을 완전히 재현하지는 않는다. 이러한 신호에 접근하거나 이를 재현하기 어렵기 때문에, SAGEO Arena는 콘텐츠 제작자가 관찰할 수 있고 문서 가시성을 개선하기 위해 직접 수정할 수 있는 통제 가능한 요인에 초점을 맞춘다. 그럼에도 더 풍부한 순위 신호와 사용자 행동 신호를 통합하는 일은 향후 SAGEO 연구의 중요한 방향으로 남아 있다.

## E StageAware SAGEO를 위한 프롬프트

SAGEO Arena에서 얻은 실증 결과를 바탕으로, 파이프라인의 각 단계에서 중시하는 요소에 맞춰 최적화를 조정하는 단계 인식 SAGEO 전략을 제안한다. 프롬프트는 표 7에 제시한다.
